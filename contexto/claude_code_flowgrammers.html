AULA 01

Por que Claude Code está no centro

A primeira aula responde à pergunta mais importante do módulo: o que significa um sistema ser o núcleo de uma arquitetura.

Se você já mexeu com Claude Code, provavelmente já notou: ele não funciona como um ChatGPT. Você não chama ele pra fazer uma coisa. Você fala um objetivo, e ele se vira.

Essa diferença parece sutil, mas muda completamente como você desenha seus projetos. Nesta aula, você vai entender por que Claude Code fica no centro da arquitetura — e não como mais uma ferramenta ao lado das outras.

O QUE VOCÊ VAI APRENDER
✓
Por que o diagrama coloca Claude Code no centro — e não as APIs, o banco ou o n8n.
✓
A diferença entre uma ferramenta passiva e um agente ativo que orquestra outras ferramentas.
✓
O conceito de núcleo ativo: um sistema que age, decide e chama os outros por conta própria.

2
Ferramenta passiva vs agente ativo

Existem dois tipos fundamentais de sistema numa stack moderna: os passivos e os ativos.

Um sistema passivo é aquele que executa o que você pede, exatamente como você pediu. Ele não tem iniciativa. O Supabase, por exemplo, é um banco de dados excelente — mas ele fica parado esperando alguém escrever SQL. O n8n também: ele espera você desenhar o workflow. O GitHub guarda o código, não escreve.

Já um agente ativo é diferente. Você fala o que quer, e ele decide sozinho como fazer. Qual ferramenta usar. Em qual ordem. O que fazer quando algo dá errado. Ele tem iniciativa.

Ferramenta passivaAgente ativo (Claude Code)
Espera você clicarAge por conta própria
Executa um comando por vezEncadeia múltiplas ações
Não toma decisõesDecide o caminho baseado no objetivo
Precisa de você do início ao fimVocê define o destino, ele se vira
O ponto-chave
Claude Code está no centro do diagrama porque ele é o único sistema ativo da arquitetura. Todos os outros esperam ser chamados. Só ele age por conta própria.
3
A analogia do maestro

A forma mais fácil de entender isso é pensar numa orquestra.

A orquestra
Imagine uma orquestra sinfônica. Cada músico é um especialista: o violinista toca violino muito bem, o tubista toca tuba, o baterista cuida do tempo. Todos são excelentes no que fazem, mas sozinhos tocariam cada um no seu ritmo, sem sincronia. O que transforma um grupo de músicos em uma orquestra é o maestro.

O maestro não toca nenhum instrumento durante o concerto. Ele lê a partitura, entende o que precisa acontecer em cada momento, e coordena quem entra quando, em que volume, com qual intensidade. Sem ele, o concerto vira ruído.

Agora aplique isso ao diagrama:

A tradução para arquitetura
O Supabase é o violinista dos dados. O n8n é o percussionista da automação. O GitHub é o baixista da versão. O WhatsApp é o trompete da entrega. Cada um faz muito bem uma coisa específica. Claude Code é o maestro: lê sua instrução (a partitura), decide quem entra primeiro, chama cada sistema na hora certa e entrega o resultado final coeso.
Lembre sempre
Se você tirar o maestro da orquestra, os músicos continuam tocando — mas cada um no seu tempo, sem sincronia. É exatamente isso que acontece sem Claude Code: os sistemas continuam funcionando, mas ninguém coordena. Você vira o maestro humano, abrindo aba por aba, conectando tudo na mão.

Chegamos ao final. Fixe esta ideia na cabeça:

Claude Code não é só mais uma ferramenta que você instala. Ele é o maestro que decide quem toca quando na sua arquitetura. Essa é a razão pela qual ele fica no centro — e tudo o mais se organiza ao redor dele.

Na próxima aula, você vai aprender a ler esse diagrama. Porque ele não é só bonito — ele tem uma linguagem própria. Cada cor, cada posição, cada conexão significa alguma coisa. E quando você aprende essa linguagem, consegue desenhar a arquitetura de qualquer projeto.

AS 4 CATEGORIAS EXPLICADAS
1
Verde — Frameworks e orquestração

Os sistemas verdes são MCP Servers, n8n e LangGraph/CrewAI. O que eles têm em comum?

Todos os três estendem o que Claude Code sabe fazer. O MCP adiciona ferramentas novas ao agente. O n8n adiciona workflows de automação empresarial. O LangGraph adiciona capacidade de trabalhar com múltiplos agentes em paralelo.

Eles não são apenas usados pelo Claude Code. Eles trabalham junto com ele, como parceiros de orquestração.

MCP Servers
n8n
LangGraph / CrewAI
A forma mais fácil de pensar
Se Claude Code é o maestro, os sistemas verdes são outros maestros convidados. Eles também sabem coordenar coisas. MCP convida novas ferramentas pra orquestra. n8n cuida da parte empresarial. LangGraph monta outra orquestra se precisar.
2
Azul — Infraestrutura e dados

Os sistemas azuis são Supabase/DB, GitHub e Docker/VPS. São a fundação física da sua arquitetura.

A característica que une os três: eles existem independentemente do Claude Code e continuam úteis mesmo sem ele. Você teria um Supabase, um GitHub e um Docker de qualquer forma, em qualquer projeto moderno. A diferença é que o Claude Code aprende a usar essas fundações automaticamente.

Supabase / DB
GitHub
Docker / VPS
Uma forma de lembrar
Os sistemas azuis são como os cimentos da casa. Não importa quem vai morar, eles precisam estar lá. Claude Code é quem mora na casa — ele usa os cimentos, mas não os substitui.
3
Amarelo — IDEs e APIs

A categoria amarela é a maior do diagrama porque reúne dois subtipos relacionados: os IDEs (onde o desenvolvedor trabalha) e as APIs (onde o código é exposto ou consumido).

Os IDEs da categoria:

Cursor / Lovable
VS Code
Antigravity

As APIs da categoria:

FastAPI / REST
Anthropic API

Os IDEs são onde você dirige o Claude Code. Cursor e Lovable têm IA nativa; o VS Code é o editor mais usado do mundo, onde Claude Code também opera via terminal ou extensão; o Antigravity é o novo IDE do Google focado em fluxo agent-first (desenvolvido para colaborar com múltiplos agentes de IA).

Já as APIs estão no mesmo grupo porque dividem a mesma lógica: não orquestram, elas expõem ou consomem. A FastAPI expõe seus agentes; a Anthropic API é o acesso direto ao modelo.

Por que IDE e API na mesma categoria
Porque todos esses sistemas são primos do Claude Code — ambientes e interfaces que usam ou hospedam inteligência artificial, mas nenhum deles tenta ser maestro. São ferramentas de desenvolvedor que trabalham com Claude Code ou paralelamente a ele.
Observação importante: Antigravity e VS Code foram adicionados à categoria para refletir a realidade de 2026. O Antigravity representa a próxima geração de IDEs já nascidos para IA multi-agente. O VS Code é o editor neutro onde Claude Code pode rodar de forma não-invasiva.
4
Vermelho — Canais de entrega e RAG

Os sistemas vermelhos são Playwright, RAG + Embeddings e WhatsApp/Slack. Eles têm um papel específico: são o ponto de contato com o mundo real.

Playwright leva o Claude Code até o navegador, conectando ao mundo via web. RAG é a memória que permite responder com contexto específico do seu negócio. WhatsApp e Slack são onde o resultado aparece para o usuário final. Os três fazem a ponte entre o agente e o mundo externo.

Playwright
RAG + Embeddings
WhatsApp / Slack
O papel deles
Tudo o que sai do núcleo precisa chegar em algum lugar. Os sistemas vermelhos são esse último quilômetro da sua arquitetura. Sem eles, o Claude Code pensa bonito mas não entrega nada pra ninguém.

AULA 03

Como uma instrução vira ação

Rastreando fluxos reais no diagrama. Do comando do desenvolvedor até o resultado entregue ao usuário final.

Nas duas primeiras aulas, você aprendeu por que Claude Code está no centro e o que tem ao redor. Agora é hora de ver a arquitetura em movimento.

Nesta aula, você vai ver como uma única instrução sua ativa múltiplos sistemas do diagrama em sequência. Isso tem um nome: caminho crítico. Lembre: no diagrama interativo da Aula 2, você pode visualizar esses fluxos clicando nos botões "Endpoint + Slack", "Monitoramento + WhatsApp" e "Refatoração + deploy".

O QUE VOCÊ VAI APRENDER
✓
Como uma única instrução ativa múltiplos sistemas em sequência.
✓
Que Claude Code decide o caminho baseado na tarefa, não aciona tudo ao mesmo tempo.
✓
O conceito de caminho crítico: sistemas obrigatórios vs opcionais por tipo de objetivo.
TRÊS EXEMPLOS REAIS
1
O conceito de caminho crítico

Antes de ver os exemplos, entenda o conceito central da aula.

Numa arquitetura com 14 sistemas, nenhuma tarefa usa todos ao mesmo tempo. Cada instrução percorre um subconjunto específico — um caminho determinado pelos requisitos da tarefa.

Esse caminho é o caminho crítico. Ele inclui só os sistemas necessários para aquela tarefa específica. Os outros ficam parados, esperando.

Por que isso importa
Entender caminho crítico é a habilidade que separa quem só usa Claude Code de quem projeta sistemas com Claude Code. Você olha pra uma tarefa e já consegue prever quais sistemas serão acionados — e em que ordem.
2
Exemplo 1 — Criando um endpoint de cadastro
A instrução
"Cria um endpoint REST de cadastro de usuário que grava no banco, dispara email de boas-vindas e manda notificação pro Slack do time."

Vamos rastrear o caminho crítico dessa tarefa, sistema por sistema:

1
CLAUDE.md — Claude Code lê o arquivo de contexto do projeto
2
GitHub (azul) — analisa a estrutura atual do repositório
3
FastAPI (amarelo) — gera o código do endpoint
4
Supabase (azul) — cria o schema da tabela de usuários
5
Bash (tool nativa) — roda os testes automatizados
6
n8n (verde) — configura o workflow que dispara email e Slack
7
Slack (vermelho) — recebe a notificação final
8
GitHub (azul) — commit, push e PR abertos automaticamente
Repare: não usamos MCP, nem Playwright, nem RAG nesse exemplo. Essa instrução não precisa deles. Cada tarefa tem seu caminho crítico próprio.
3
Exemplo 2 — Monitoramento + relatório automatizado
A instrução
"Monitora o site de licitações do governo todo dia às 8h, extrai as novas publicações da área de tecnologia, salva num banco vetorial e gera um briefing executivo em PDF enviado por WhatsApp."

Essa tarefa é bem mais complexa. Veja o caminho:

1
n8n (verde) — agenda o trigger diário às 8h
2
Playwright (vermelho) — acessa o site e extrai os dados
3
Claude Code (núcleo) — analisa e classifica o conteúdo
4
RAG + Embeddings (vermelho) — gera embeddings e armazena
5
Supabase (azul) — persiste os metadados
6
Anthropic API (amarelo) — gera o briefing executivo
7
Docker / VPS (azul) — gera o PDF no servidor
8
WhatsApp via n8n — entrega o briefing ao usuário
Observação importante
Esse caminho passa por todas as 4 categorias (verde, azul, amarelo e vermelho). É um fluxo completo que mostra o poder da arquitetura integrada. Mas note: continuou não usando MCP, nem GitHub, nem LangGraph.
4
Exemplo 3 — Refatoração com deploy
A instrução
"Refatora esse módulo de autenticação pra usar JWT com refresh token, atualiza os testes e faz o deploy em staging."

Esse exemplo é mais "centrado em desenvolvedor":

1
VS Code (amarelo) — Claude Code opera dentro do IDE do desenvolvedor
2
MCP Servers (verde) — acessa contexto via MCP
3
GitHub (azul) — cria branch e faz commits
4
Bash (tool nativa) — roda os testes após cada mudança
5
Docker (azul) — faz build da imagem atualizada
6
VPS (azul) — deploy em ambiente de staging
7
GitHub (azul novamente) — abre PR com descrição
Padrão interessante: esse exemplo usa muito da faixa amarela e azul, quase nada de vermelho. É uma tarefa interna, sem entrega externa imediata. Repare que o IDE escolhido poderia ser Cursor ou Antigravity — o caminho funciona com qualquer um deles.

AULA 04

O que Claude Code não substitui

Limites arquiteturais, responsabilidades e onde o humano continua no loop. A aula mais estratégica do módulo.

Depois de três aulas mostrando o poder do Claude Code, existe um risco: você começar a achar que ele substitui todo mundo. Isso é um erro — e um erro que pode custar caro.

Nesta aula, você vai ver exatamente o que Claude Code não substitui — e por que isso é uma boa notícia pra quem quer construir arquiteturas confiáveis, não sistemas frágeis.

O QUE VOCÊ VAI APRENDER
✓
Por que cada sistema do diagrama continua existindo, mesmo com Claude Code.
✓
Os limites do núcleo: o que Claude Code decide sozinho vs o que precisa de aprovação humana.
✓
Como posicionar checkpoints humanos na arquitetura de forma estratégica.
CONTEÚDO DA AULA
1
Por que cada sistema continua existindo

Uma pergunta justa: se Claude Code é tão poderoso, por que eu preciso do Supabase? Por que manter o n8n? Por que o GitHub?

A resposta é que cada um desses sistemas faz muito bem uma coisa específica — e essa coisa não é o que Claude Code faz. Observe:

SistemaPor que Claude Code não substitui
SupabaseArmazena dados persistentes, aplica regras transacionais, escala horizontalmente
GitHubVersiona código de forma confiável, mantém histórico auditável
n8nExecuta workflows agendados 24/7 sem depender do Claude estar ativo
DockerGarante reprodutibilidade do ambiente, isola execuções, padroniza deploy
WhatsApp / SlackSão onde os humanos já estão — Claude Code não tem audiência própria
O ponto central
Claude Code é excepcional em pensar e orquestrar. Mas não é bom em persistir 10 milhões de registros. Não é bom em ficar 24 horas no ar esperando eventos. Cada sistema ao redor faz uma coisa muito bem. Claude Code também: coordenar os outros. Ninguém aqui é redundante.
2
Autonomia vs supervisão humana

Este é o conceito mais importante da aula inteira.

Existe um espectro. Num extremo, decisões operacionais rotineiras que Claude Code resolve sozinho. No outro extremo, decisões com impacto irreversível, custo alto ou exposição pública — essas sempre passam por você.

Decisões que Claude Code pode tomar sozinho
  1. Escolher qual biblioteca importar para resolver um problema técnico
  2. Organizar a estrutura interna de um arquivo de código
  3. Escrever testes unitários para funções existentes
  4. Fazer commits locais e criar branches novas
  5. Consultar documentação e buscar exemplos na web
Decisões que precisam de aprovação humana
  1. Fazer deploy em produção
  2. Apagar registros de banco de dados ou deletar arquivos
  3. Enviar mensagens em nome da empresa para clientes externos
  4. Gastar recursos pagos (APIs, infraestrutura) acima de um limite
  5. Mudanças arquiteturais que afetam múltiplos módulos
A regra geral
Claude Code decide sozinho o que é reversível, barato e interno. Você decide o que é irreversível, caro ou público.
3
Como posicionar checkpoints no fluxo

Na prática, como você garante que o humano entra no loop na hora certa, sem virar gargalo?

Existem padrões conhecidos. Aprenda esses cinco:

1
Checkpoint de aprovação antes de deploy — Claude Code faz tudo até gerar um PR. Humano aprova o merge.
2
Checkpoint de limite de custo — acima de X reais gastos em API, o agente para e pede autorização.
3
Checkpoint de comunicação externa — toda mensagem para clientes passa por revisão humana.
4
Checkpoint de dados críticos — qualquer deleção ou update massivo aguarda confirmação.
5
Checkpoint de escalação — quando o agente fica "confuso" por mais de N iterações, escala.
Human-in-the-loop consciente
Coloque o humano exatamente onde ele agrega valor: em decisões irreversíveis, caras ou com exposição pública. E tire o humano de todo o resto.

CONTEÚDO DA AULA
1
Template vs projeto real

O diagrama completo que você viu no módulo inteiro é um template. Um menu de possibilidades. Mas cada projeto real usa um subconjunto específico.

Para te ajudar a decidir, vou mostrar quatro arquétipos de arquitetura. Cada arquétipo é adequado a um tipo de projeto diferente.

2
Arquétipos minimalistas

Estes dois arquétipos usam poucos sistemas, mas resolvem muito.

Arquétipo 1 — Agente solo
Sistemas: Claude Code + GitHub + Anthropic API + VS Code (ou Cursor/Antigravity)

Quando usar: desenvolvimento individual de scripts, prototipagem, projetos pessoais.

Exemplo real: um dev criando uma biblioteca open source ou um MVP pessoal.
Arquétipo 2 — Automação interna
Sistemas: Claude Code + n8n + Supabase + Slack

Quando usar: automações internas para times.

Exemplo real: um bot de status diário que coleta métricas e resume pro time.
Observação importante: esses dois arquétipos atendem 80% dos projetos do começo da sua jornada. Comece com 4 sistemas e adicione o resto quando o problema aparecer.
3
Arquétipos completos

Agora os arquétipos maiores. Use quando o projeto exige escala.

Arquétipo 3 — SaaS com IA como produto
Sistemas: Claude Code + Supabase + pgvector + FastAPI + Docker + VPS + GitHub + MCP + Playwright + Stripe

Quando usar: SaaS onde a IA é o produto.

Exemplo real: plataforma de diagnóstico empresarial com IA atendendo 500 clientes simultâneos.
Arquétipo 4 — Automação empresarial de ponta

Quando usar: múltiplos agentes coordenados, monitoramento contínuo.

Regra de ouro
Não é "quanto mais sistemas, melhor". A complexidade tem custo. Só escale quando o problema exigir.

O teste final
Um bom diagrama é aquele que um novo dev consegue entender em 3 minutos. Se precisa de 20 minutos de explicação, o diagrama está ruim.

OS 5 TAKEAWAYS DO MÓDULO

AULA 01 · O MAESTRO
Claude Code é o maestro. Ele decide, coordena e orquestra — enquanto os outros sistemas executam. É o único componente ativo.

Verde orquestra, azul sustenta, amarelo expõe, vermelho entrega. Cada cor é um tipo de relação com o núcleo.

📐
AULA 05 · SEU DIAGRAMA
