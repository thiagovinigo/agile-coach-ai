👆 O que em Pronto pode cruzar o Commitment Point agora?
💬 Suas falas

"Em Dev temos [N] vagas abertas. Vamos olhar o que está em Pronto e decidir o que realmente está pronto para cruzar — não o que gostaríamos que cruzasse."

[Aponta para Pronto. Não abre discussão de prioridade geral. Replenishment não reprioriza o backlog inteiro.]

Perguntas — nessa ordem

A
Esse item tem critério de aceite escrito e aprovado? Se não, volta para Refinamento.
Esse é o guardião do Commitment Point. Item sem critério de aceite não cruza — mesmo que o time "saiba o que fazer".
B
Tem dependência externa não resolvida — design, API de terceiro, outra equipe?
Uma dependência não resolvida é um bloqueio que ainda não aconteceu. Melhor descobrir agora do que no meio do Dev.
C
Qual é a classe de serviço? Isso define a posição na fila.
Standard entra por FIFO. Fixed Date tem prazo declarado. Expedite tem protocolo separado. Intangível tem prioridade mínima.
💡Replenishment ≠ Sprint Planning. Você não está comprometendo um bloco de tempo nem estimando em horas. Está preenchendo capacidade com o que está realmente pronto. Se demorar mais de 30 minutos, o problema está no refinamento — os itens não estavam prontos de verdade.
📋 Exemplo

"Integração PIX" queria cruzar. Pergunta B revelou que a documentação da API do banco ainda não estava disponível. Voltou para Refinamento. Dev puxou outro item pronto — e o PIX entrou na semana seguinte sem surpresas nem bloqueio no meio do ciclo.
